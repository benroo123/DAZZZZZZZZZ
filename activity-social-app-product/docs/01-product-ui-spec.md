# 产品与 UI 规格

## 1. 产品定位

一句话：帮助城市用户围绕一件具体活动，在合适的时间与地点，找到可信、能到场的搭子。

核心差异不是再做一个 Tinder 式滑卡，也不是复制小红书内容流，而是把关系建立的最小单位从“聊天/关注”改成“共同完成一次活动”。

### 用户价值闭环

1. 用户从首页内容获得活动灵感。
2. 搜索或筛选到可参与的同城活动。
3. 查看组织者、参与者、人数、时间、地点和安全信息。
4. 申请加入，必要时由组织者审核。
5. 加入活动群，完成行前沟通、签到和活动。
6. 评价履约与体验，形成下一次推荐和复组依据。

## 2. 信息架构

底部五个一级入口固定为：首页、搭子、发布、消息、我的。搜索只出现在首页，避免跨页面重复入口。

### 首页

- 顶部“推荐 / 同城”为单击分段控件；双击只可用于刷新。
- 统一搜索实体：活动、地点、帖子、用户、名称关键词。
- 搜索框右侧为筛选按钮，打开手机底部弹层。
- 筛选项：活动类型、地点、距离、时间、人数；后续可增加门槛、费用、是否实名。
- 活动与动态混排。活动用“活动”标签、剩余名额、时间地点和人数；动态用“动态”标签、作者和互动数据。
- 排序默认同时考虑相关性、距离、时间可参与性、活动成局概率、质量和安全风险；不能只按热度。

### 搭子

- 大图是主信息，展示昵称、年龄、公开 ID、实名认证状态、距离粗粒度、兴趣、简介。
- 滑卡只是发现方式；匹配后优先推荐“共同可参加的活动”，把聊天导向真实场景。
- 实名状态可见，实名原始信息永不公开。
- 精确位置、电话、身份证信息不得进入匹配卡或 Agent 上下文。

### 发布

- 支持“发起活动”和“发布动态”。
- 发布必须有至少一张图片。
- 无图时可根据标题和正文异步生成封面；生成后必须让用户预览、替换或重新生成，用户确认后才能发布。
- AI 图片需显式显示“AI 生成内容”，文件侧保留可追踪的隐式标识和生成记录。
- 活动必填：标题、正文、图片、开始/结束时间、地点、人数下限与上限、加入方式。
- 人数范围后端强校验为 `2 <= min_participants <= max_participants <= 50`。

### 消息

- 顶部展示关注、被关注和新增关注入口。
- 下方对话列表混合活动群、私信与系统消息，通过文字标签区分。
- 每个对话支持免打扰、举报和静默屏蔽。
- 静默屏蔽不通知对方；对方后续消息进入隔离区或直接不可达，具体策略需在隐私说明中明确。
- 活动群成员由活动成员关系自动同步，不允许任意绕过活动资格加入。

### 我的

- 基础资料：头像/生活照、昵称、年龄、性别可见性、城市、简介、兴趣、作息、可参与时段、活动偏好、人数偏好。
- 信任资料：实名认证状态、履约率、活动评价；展示结果，不展示原始凭证。
- 每一项应有可见范围：公开、仅匹配对象、仅活动成员、仅自己。
- 资料完整度只用于解释如何提升匹配，不应制造羞辱性“社交分”。

## 3. 关键状态

### 活动状态

`draft -> pending_review -> published -> full -> ongoing -> completed`

异常分支：`cancelled`、`rejected`、`suspended`。人数已满后新申请进入候补；成员退出后按候补顺序并结合组织者审核策略补位。

### 参与状态

`applied -> approved -> joined -> checked_in -> completed`

异常分支：`waitlisted`、`rejected`、`cancelled`、`removed`、`no_show`。

## 4. 信任与安全设计

- 首次私信、加群、活动集合地点变更、收款信息都触发风险提示或检测。
- 组织者不能看到申请者手机、证件和精确常住坐标。
- 活动发布先经过文本、图片、地点、风险词与用户信用的组合审核；高风险进入人工队列。
- 线下活动提供一键举报、紧急联系人、行程分享和签到能力。
- 拉黑关系在搜索、推荐、匹配、活动成员预览和消息五处统一生效，不能只在聊天层过滤。
- 评价采用活动后双盲开启，减少报复性评价。

## 5. 视觉系统

### 首发建议：清透蓝

蓝色用于主行动、选中状态和活动标签；紫色仅表示动态；橙色用于名额紧张和提示。大面积背景保持白色或浅灰，避免“社交 App 廉价渐变感”。

### 三套方向

| 方向 | 主色 | 气质 | 建议用途 |
|---|---:|---|---|
| 清透蓝 | `#0A84FF` | 可信、克制、现代 | 首发全局主题 |
| 极光青 | `#00A9B7` | 科技、呼吸感、社区 | 品牌差异化备选 |
| 日出橙 | `#FF694A` | 热情、年轻、行动 | 城市活动季或增长主题 |

## 6. 验证假设

原型上线前做 15–20 人任务测试，至少覆盖“找今晚活动”“创建 6 人活动”“发现并屏蔽陌生私信”“完善资料后匹配”四条任务。MVP 上线后优先验证：活动供给密度、申请到成局的漏斗、到场率和安全事件，而不是 DAU 本身。
